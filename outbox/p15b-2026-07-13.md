## TASK 0 — Probe

Ran the doc's exact specified command:
```bash
grep -n "return" src/index.js | awk -v s=$(grep -n "async function handleJournalismCycle" src/index.js | head -1 | cut -d: -f1) '$1>=s && $1<=s+400'
```

**Real bug found in the doc's own probe command**, not silently worked
around: the output included spurious low-numbered matches (lines
587-618) that have nothing to do with `handleJournalismCycle` (which
starts at line 5794). Root cause: `awk`'s `$1` field from `grep -n`
output is a string like `"587:"` (colon attached, no space) — since it
contains a trailing non-digit character it is not a valid POSIX numeric
string, so the comparison `$1>=s` silently falls back to a **string**
comparison against `s` (`"5794"`). Lexicographically, `"587:"` sorts
above `"5794"` (`'8' > '7'` at the second character), so the filter
let it through despite being nowhere near the real function.

Used a corrected version instead (`awk -v s=... '{split($1,a,":"); if
(a[1]>=s && a[1]<=s+400) print}'`) and, more reliably, read the actual
function body directly with the `Read` tool rather than trusting grep
line-slicing alone — this is what actually mapped the real control flow
used for TASK 1.

**Real function boundaries confirmed at current HEAD** (all line numbers

## Real finding: the bug is broader than the original diagnosis

Read the complete morning-brief `if` block
(`if (isMorningWindow && env.WC2026_DB && env.JOURNALISM_QUEUE) { try {
... } catch(e) { ... } }`) line by line to check every path, not just
the one the doc's CONTEXT names (the `alreadyRan` dedup hit):

- `alreadyRan` → `return {ok:false, reason:'wc morning brief already ran today'}`
- no recent WC results → `return {ok:false, reason:'no recent WC results for morning brief'}`
- success → `return {ok:true, reason:'wc morning brief enqueued', ...}`
- `catch(e)` → `return {ok:false, reason:'wc morning brief error: ' + e.message}`

**Every single path inside this block returns.** There is no fall-through
case. This means the original June 20 diagnosis ("catch-up never
executes... after the first successful morning-brief run that day") was
correct about the mechanism but understated the impact: catch-up was
unreachable for the **entire 11:00-13:00 UTC window**, every tick,
whenever `WC2026_DB`/`JOURNALISM_QUEUE` are bound — including the very
first tick of the day, the no-results case, and the error case — not
only on ticks after the dedup guard specifically fired. Reported here
plainly rather than silently building the fix around the narrower
premise (Rule 72).

## TASK 1 — Relocation (with a real dependency the doc's instruction didn't account for)

The doc's TASK 1 said: "Relocate the full archive catch-up block (`let
_catchupFilled = 0` through its closing log)." A literal reading of
that alone would have broken the function: the catch-up block iterates
`gameMeta`, which is built by an ESPN-scoreboard fetch loop
(`LEAGUES`/`gameLines`/`gameMeta`) that itself sits **after** the
morning-brief block, further down in the function. Moving only the
28-line catch-up snippet without its dependency would have produced a
`ReferenceError: gameMeta is not defined` the first time the relocated
code actually ran — a real, load-bearing gap in the doc's own
instruction, not something to blindly copy.

**Actual fix implemented**: moved the catch-up block **and** its
dependency (`LEAGUES` array + the ESPN-fetch loop that builds
`gameLines`/`gameMeta`) to execute immediately after the dead-hours
early-return, ahead of the WC morning-brief check. The
`if (!gameLines.length) return {...}` early-return check was
deliberately **left in its original position** (right before the
"Pre-game slate seed" section) rather than moved — moving it too would
have made an empty ESPN response abort the whole function before the
morning-brief block ever got a chance to run, a real regression the doc
never asked for and TASK 2 explicitly forbids ("morning-brief logic
itself unaffected"). Since `gameMeta`/`gameLines` are empty in that
same case, the relocated catch-up loop over an empty array is a
harmless no-op — this preserves the "no game lines" behavior exactly
for both paths.

The whole relocated block is wrapped in its own `try/catch` (the
existing per-league inner catches were kept as-is; added one more
outer layer) so a failure there can never block the WC morning-brief or
slate-brief paths that follow it (Rule 5) — matching the same safety
property the code already had before being moved.

`git diff` confirms: 138 insertions / 124 deletions, and critically —
the WC morning-brief block's own internal lines are **byte-identical**;
zero `+`/`-` lines appear inside it. Only its position relative to
catch-up changed (catch-up now precedes it).
