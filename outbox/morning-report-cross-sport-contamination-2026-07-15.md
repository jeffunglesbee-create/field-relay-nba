## TASK 1 — Fix (the real, honest sequence, not just the final result)

**Attempt 1 (commit 45bbe89):** added a prompt instruction and a structural guard (verify both real team names appear whenever a real game's score appears in the generated prose) based on the incorrect `/v2/games`-shape assumption above. Deployed successfully. `node --check` clean.

**Live verification of attempt 1 found it insufficient, live, in real time:** triggered a real recompute (see TASK 1's recompute-route addition below) to test the fix against live data. The regenerated text **still contained "Chicago Fire"** — the guard did not fire. Debugging this discrepancy directly (not assumed) led to discovering the real `ctx.games` bare-mascot shape described in TASK 0 above: a plain substring-presence check (`prose.includes("Fire")`) cannot distinguish correct "Fire" usage from "Chicago Fire", since both literally contain the substring "Fire".

**Attempt 2 (commit 2b85f1b, the real, verified fix):** revised both the prompt instruction (explicitly: use each team's name exactly as given, never add a city/league qualifier not present in the data) and the structural guard. Since the data never supplies a city, there's no way to verify a city-qualified reference is *correct* either — so, matching this repo's established fail-safe convention (e.g. `_bsdEventIsLive`'s "uncertain → treat as risk"), the guard now rejects **any** invented city/qualifier immediately in front of a real team's bare mascot, not just outright wrong-team swaps. Verified via a forced-condition test suite (6 cases: the real original incident text, the real second live-recurrence text, correct bare-mascot usage, sentence-initial mascots, a partial brief, null prose) — all passed, including both real failure texts.

**Deployed and re-verified live, this time successfully:** a fresh recompute produced "the Sun edged out the Fire 90-87 in a thrilling WNBA contest" — real team names, no fabricated city, real score, correctly attributed.

**Infrastructure needed to make this real live verification possible at all:** `morning_report` is AI-costing and deliberately never auto-fired outside the daily `0 9 * * *` cron (Rule 78), and `analyticsEngine`'s own watermark refuses to re-run an already-processed date — there was no existing way to correct an already-published brief without waiting for tomorrow's cron. Added `POST /analytics/morning-report/recompute?date=` (reuses the existing, already-correct `night_stars`/`truth_is` D1 values rather than recomputing them — one real LLM call only) and `POST /analytics/circadian-late/recompute?date=` (reuses the existing generic `recomputePhase`, no LLM cost, just refreshes the copy) — both mirror the existing `/analytics/jinx/recompute` auth/shape pattern exactly. One real bug caught and fixed in the same pass: the new routes were initially missing from this relay's explicit non-GET-method allow-list (the same list `/analytics/jinx/recompute` is in) — a real, self-caught 405, fixed immediately (commit `819be05`, folded into this same dispatch's real-fix trail).
